# 机场地面保障调度管理系统

面向航班机位分配、廊桥调度、行李转运、货物装卸、航空加油、航食配餐与客舱清洁全流程的机场地面保障调度管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-handling:entries` 这一项，或调用 `resetModule(模块)`。

## 地面电源的权限与归属护栏

地面电源模块（`ground_power`）在普通状态流转之外，额外有一套管辖护栏（规则集中在
`frontend/src/data/ground-power-policy.ts`，拦截逻辑在 `local-service.ts` 的
`updateGroundPower` 里兜底，页面绕不过去）：

- **受控字段**：设备编号、所属机位、输出电压、额定电流。只有设备「归属航站楼」对应的
  **本航站楼维护组**能改动；地勤、加油等其他单位只能查看，越权提交直接拦截、一条字段都不改。
  顶栏可切换值班单位演示只读/可编辑两种身份。
- **归属航站楼**：是设备的管辖归属，不由任何编辑提交写入或修改；缺归属的**历史设备**在数据
  首次读取时按管辖范围自动回填——机位编号带本楼前缀（`T1-`/`T2-`/`T3-`）归该楼，共享机位等
  无法辨认的按设备编号稳定轮派。回填只补这一个字段，受控记录的旧值一律不动；已带归属的记录
  原样保留，回填幂等。
- **共享机位**：`TS-` 前缀为多楼共用机位，机位信息（设备的「所属机位」字段）保持只读，不能改派；
  也不允许把本楼设备改派到其他航站楼的机位。
- **确认断电联动**：地面电源「结束供电」成功后，其它入口——地勤排班清单（`crew_schedule`，通过
  「关联设备」字段挂接）里仍占用该设备的待办会同步释放（流转为「已离岗」、待办标记清除）。
  页面返回信息会带上释放条数。
- **重复提交只生效一次**：已断电的设备再次「结束供电」会被拦截（不会重复释放）；受控字段编辑
  提交内容与现状完全一致时判定为重复提交，不重复落库；同一设备动作进行中页面按钮禁用，防连点。
- 校验脚本：`cd frontend && npm run verify:ground-power`（越权拦截、共享机位只读、跨楼改派、
  断电联动释放、幂等、历史回填共 20+ 条断言）。
